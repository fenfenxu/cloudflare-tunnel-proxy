# Cloudflare Tunnel Proxy

个人翻墙 / 代理方案：**用 Cloudflare 隧道，把一台能访问外网的「翻墙机器」接到你自己的电脑上。**

## 这套方案是什么

你要的不是「再买一个商业 VPN 账号」，而是一条**自己掌控**的个人代理链路：

1. 有一台能常开、能访问外网的机器（VPS、家里电脑、Bot 电脑等）——我们叫它 **翻墙机器**。
2. 在翻墙机器上只监听本机的一个小代理，再经 **Cloudflare 命名隧道** 发到你的域名。
3. 在你的电脑上用 `cloudflared access tcp`（可选 Clash）连这条隧道；用邮箱 OTP 登录 Cloudflare Access 鉴权。

合在一起，就是：

```
你的电脑（Clash / cloudflared access tcp）
  → Cloudflare Access（邮箱一次性验证码）
  → Cloudflare 命名隧道
  → 翻墙机器上的本机代理（只绑 127.0.0.1）
  → 从翻墙机器出口访问外网
```

**成功标准（给用户的一句话）：** 在你的电脑上，带鉴权访问探测地址返回 **HTTP 204**（例如 Google `generate_204`）。

### 用语（请始终用这两套词）

| 用语 | 指什么 |
|------|--------|
| **你的电脑** | 日常使用的客户端：Clash、`cloudflared access tcp`（常见是 Mac） |
| **翻墙机器** | 常驻跑「本机代理 + Cloudflare 命名隧道」的那台 |

不要对用户说 Origin / ingress 等内部词。

### 你需要具备什么

- 免费 Cloudflare 账户  
- **自己的域名**并接到 Cloudflare（不能只用 `*.trycloudflare.com`）  
- 一台可常驻的翻墙机器  
- 域名可用支付宝 / 微信等自行付款购买（助手不代付、不推联盟链接）

### 已知限制

出口 IP 常是 Cloudflare / 机房地址，**部分网站（如 OpenAI / Codex）可能不可用**——这是方案限制，不是安装失败。

### 三种用法

| 模式 | 什么时候 |
|------|----------|
| **Setup** | 从零搭梯子 / 翻墙 / CF 代理 |
| **Doctor** | 挂了、不通、health；分层查「你的电脑 / 翻墙机器」并尽量自动修 |
| **Monitor** | 保活：优先翻墙机器上的 cron/脚本；助手例程只做 OTP 等必须人工的兜底 |


## 安全方案说明

这套方案把「谁能连」「端口露不露公网」「密码放哪」分开处理，少一层出事少一层：

1. **Cloudflare Access 邮箱 OTP**  
   陌生人没有你的邮箱验证码进不了隧道入口。授权/会话通常大约 **24 小时**，过期要在你的电脑上重新 OTP，不是翻墙机器坏了。

2. **翻墙机器上的代理只绑 `127.0.0.1`**  
   本机 CONNECT 代理不监听公网网卡。外网直接扫端口连不上；只有经过 Cloudflare 隧道的流量才能到这个端口。

3. **CONNECT 再加一层 Basic 鉴权**  
   即便有人摸到本机端口，没有 `proxy.auth` 里的用户名密码也会被拒（常见是 HTTP 407）。

4. **绝不把代理端口公开暴露**  
   不要用 `0.0.0.0`、不要在防火墙/安全组放行这个端口、不要把临时 `trycloudflare` 当生产入口。

5. **密码与鉴权文件怎么存**  
   - 随机强密码，不要用文档里的示例串、不要「无密码」或弱密码  
   - `proxy.auth`、隧道凭证等文件权限建议 `600`（仅本人可读）  
   - **不要**把真实密码写进聊天、记忆、本仓库的 skill/README  

6. **破坏性操作与付款**  
   - 删隧道、换域弃用旧域、杀进程前要你确认  
   - 域名购买/续费付款只由你本人完成；助手不代付

## Setup 硬禁止（搭的时候别踩）

助手和你自己搭的时候，下面这些一律 **不要做**：

| 禁止 | 为什么 |
|------|--------|
| 无密码、弱密码、或照抄文档示例密码 | 本机端口一旦被摸到会直接沦陷 |
| 代理监听 `0.0.0.0` / 公网网卡 | 等于把 CONNECT 代理暴露到公网 |
| 只用 `*.trycloudflare.com`、不买/不接自有域名 | Access TCP + 稳定主机名做不了；本方案 **NO-GO** |
| 把 `proxy.auth` 或真实密码写进 skill、README、聊天、记忆 | 会泄露；文档只用占位符 |
| 提联盟 / 返佣 / referral 链接 | 本仓库禁止；买域名只用注册商官网 |
| 没完全退出 Clash / 系统代理就跑预检 | 结果被 fake-ip / 套娃污染，误判「网络不行」 |
| 引导「续费原来那个便宜域名」 | 到期前换新的便宜域再迁移；不要默认续费旧域 |
| 用「1.1.1.1 通不通」当总开关 | 不能代替 Cloudflare 预检脚本 |
| 开场说含糊的「能上网」 | 要说清：本机网络能摸到 Cloudflare（先预检） |
| 一次甩 3～5 个域名名让你挑 | 助手只推 **一个** 短名直接进入购买 |
| 助手代付域名 / 默认写「用信用卡结账」 | 支付宝或微信扫码，**你本人付** |

完整硬停条件见 `SKILL.md` 的 **F**；更多坑见 **G**。

## 常见问题（FAQ）

**Q1. Access 授权会过期吗？**  
会。会话常见大约 **24 小时**。过期后你的电脑上的 `cloudflared access` 要重新邮箱 OTP，再重启 `access tcp`。这不等于翻墙机器挂了。

**Q2. OpenAI / ChatGPT / Codex 打不开算搭建失败吗？**  
不算。出口常是 Cloudflare / 机房 IP，这些站点可能被拦——是已知限制。成功标准是探测地址返回 **HTTP 204**（例如 Google `generate_204`）。

**Q3. Doctor / 诊断要在哪台机器跑？**  
要分角色：**翻墙机器**上看本机代理和隧道进程；**你的电脑**上看 Access、`access tcp`、Clash。在你的电脑上却去判翻墙机器的隧道进程，容易误报「挂了」。脚本可用 `ROLE=client` 或 `ROLE=host`。

**Q4. 什么是「隧道假活」？**  
翻墙机器上本地指标看起来还连着（例如 `ha_connections ≥ 1`），但 Cloudflare 面板/API 里隧道已经是 down、没有可用连接。只看本机进程会以为正常，实际 Access 常报 `websocket: bad handshake`。保活必须交叉验证 Cloudflare 侧状态，假活时要强制重启该隧道进程。

**Q5. Clash 开着做预检为什么不行？**  
Clash TUN / fake-ip 会污染 DNS（常见 `198.18.0.0/15`），预检会误判。Setup 前请完全退出 Clash / Verge 等，并关掉系统 HTTP/HTTPS/SOCKS 代理，再跑预检。

**Q6. Clash 已经给了 DIRECT，怎么还会「套娃」、握手失败？**  
常见漏了 **IPv6**：只排除了 Cloudflare 的 IPv4，`cloudflared` 仍可能经 TUN 的 IPv6（例如源地址像 `fdfe:dcba:…`）去连 `2606:4700::`，于是 `bad handshake`。Merge 里的 `tun.route-exclude-address` 要同时排除 Cloudflare 的 IPv4 **和** IPv6。

**Q7. 为什么必须自己的域名，不能只用 trycloudflare？**  
稳定主机名 + Access 策略要绑在你自己的 zone 上。`trycloudflare` 临时链接不在本方案支持范围内。

**Q8. 密码忘了或怀疑泄露怎么办？**  
在翻墙机器上重新生成随机 `proxy.auth`（权限 `600`），重启本机代理，并更新你的电脑 / Clash 里保存的用户名密码。不要把新密码发回公开聊天或写进仓库。

**Q9. 域名快到期了要续费吗？**  
本方案默认 **不引导续费**原便宜域：到期前再买一个新的便宜域名，把隧道主机名、DNS、Access、客户端都迁过去，旧域弃用。付款仍由你本人完成。
